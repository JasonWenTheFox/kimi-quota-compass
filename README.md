# Kimi 用量罗盘 / Kimi Quota Compass

Kimi 网页版会员用量面板（Tampermonkey 用户脚本）。

## 功能

- 月度额度池使用比例，按功能拆分（Kimi Code / Kimi Work / 网站构建 / Agent / Swarm / Chat …）
- Kimi Code 5 小时 / 7 天窗口：使用比例、内部额度单位、重置时间
- 逐条额度流水（时间、功能、条目、消耗比例）
- **自动翻页回填**：官方流水接口每页 20 条，脚本会顺着 `pageToken` 一直翻到当前计费周期起点，不再只抓到最新 20 条
- **周期快照**：每次打开页面记录一份官方百分比，月度重置前会用最后一条快照固化上个周期的终值
- **历史周期视图**：下拉切换周期，月度卡与流水表都跟着切换。历史周期只显示快照里固化的官方终值；没有快照就显示「官方终值未捕获」，不会拿本地合计冒充总量
- **疑似官方重置与额度增量**：Kimi 偶尔会在账单周期中重置用量。脚本从官方读数的突然下降识别「疑似官方重置」，把实际降幅记成本周期的额度增量；不会硬编码官方的「25%」规则，也不会联网抓公告
- **导出**：JSON（含快照、周期终值与重置事件）与 CSV（每条流水），两个按钮分别导出
- 金额换算为**可选项**：留空则不显示任何金额；填了才按 `¥ / 1%` 估算
- 订阅套餐选择（老套餐 / 新套餐），老套餐带「已实测」标记并给出参考值

## 重要说明

- **官方会员接口不提供网页/会员侧的逐请求真实 Token 明细。** 面板中所有金额均为按公开 API 牌价折算的估算值，不是官方账单。
- 5h / 7d 窗口显示的 `used / limit` 是 Kimi 内部额度单位（quota units），**不是 Token**。
- **服务端只保留当前计费周期的流水**，月度重置后历史即被清空。脚本会把抓到的流水永久累积在**本浏览器** IndexedDB 中（不跨设备同步），并单独维护一张周期快照表；换浏览器、清站点数据会一起丢失，建议定期用「导出」备份。
- 月度总比例与 Code 占比使用官方接口数值；其他功能为本地累计结果。若本地没抓全，面板会显示「插件未捕获」与「数据完整度」。有疑似重置时，面板会把「官方当前」和「本周期累计（含重置）」分开显示。
- 抓取时机：页面打开即抓（含翻页回填）、切回页面即抓、前台每 60 秒抓一次。

## 疑似官方重置与额度增量

Kimi 的会员接口没有「重置记录」字段，流水里也没有单独的重置条目。脚本只能从数据本身判断：

- 页面每 4 分钟写一条官方读数快照；同一账单周期内读数突然大幅下降时，记一条「疑似官方重置」。
- 实际增量 = 重置前读数 − 重置后读数。比如重置前 18.56%、重置后 0%，本周期总额度就是 118.56%；如果是 60% → 35%，增量 25%，总额度 125%。脚本不需要知道官方规则是不是 25%，只看实际掉了多少。
- 本周期累计消耗 = 官方当前读数 + 历次实际增量；剩余额度仍以官方当前读数为准。
- 页面开着时，快照能把重置时间定位到约 4 分钟；页面关着时只能显示「检测到重置，实际时间未知」。
- 每条重置记录都能「取消此重置」或「恢复」。取消只影响计算与显示，不删除快照、流水或重置记录本身。
- 5 小时 / 7 天窗口是滚动窗口，不参与月度额度增量计算；重置时它们归零会直接体现在各自卡片上。
- 账单周期按官方 `currentStartTime` / `nextBillingTime` 显示（通常是 30 天，不是自然月）；实际扣费可能提前，脚本不跟踪扣费。

## 金额换算（可选）

面板里的金额 = 额度百分比 × 每 1% 的 API 等价值。官方只给百分比，所以这个系数必然是一个估算值。
**两个输入框留空时，界面完全不显示金额**，只显示百分比与流水。

- 老套餐（Andante / Moderato / Allegretto / Allegro）：有实测参考值，选中套餐后可一键填入 Code ¥21、其他 ¥6（每 1%）。
- 新套餐（Go / Plus / Pro / Max / Ultra）：**未实测**。新套餐取消了 Kimi Code 的额度补贴，老套餐的参考值不适用，请自行校准或留空。

用真实请求反推的参考值（2026-10 实测）：

各档位参考值（选中套餐后自动带入，也可手动改）：

| 套餐 | Code ¥/1% | 其他 ¥/1% | 依据 |
|---|---|---|---|
| Andante ¥49 | 1.1 | 0.3 | 按额度倍数推算，未实测 |
| Moderato ¥99 | 4.2 | 1.2 | 按额度倍数推算，未实测 |
| **Allegretto ¥199** | **21** | **6** | **实测** |
| Allegro ¥699 | 62 | 18 | 按额度倍数推算，未实测 |
| Go / Plus / Pro / Max / Ultra | 留空 | 留空 | 未实测，请自行校准 |

推算方法：以 Allegretto 实测的 ¥21 / 1% 为基准，按各档 Kimi Code 月额度倍数（第三方口径 28M / 108M / 540M / 1600M）等比缩放；"其他"按实测的 code/3.5 折算。**老套餐的 Code 有额度补贴，1% 能换到的 token 量随档位差几十倍，所以不能共用同一个数。**

实测口径（Allegretto）：

| 场景 | 每 1% 月池 ≈ |
|---|---|
| Kimi Code（agentic 编码，95% 输入命中缓存） | ¥21 |
| 网页 Agent / Kimi Work 类 | ¥3–9 |

原因是额度计费与 API 牌价不成比例：缓存命中的输入在 API 里按 ¥2/百万计价，在额度池里几乎免费；而网页类功能的单位 token 扣费明显更高。**同一个百分比，花在 Kimi Code 上换到的 API 价值大约是网页/Work 类的 3–7 倍。**

公开 K3 API 参考价目（每百万 token）：

| 项目 | CNY | USD |
|---|---|---|
| 输入（缓存命中） | ¥2 | $0.3 |
| 输入（缓存未命中） | ¥20 | $3 |
| 输出 | ¥100 | $15 |

- `k3` 在上下文超过约 256K 后，额度消耗约为原来的 2 倍（实测主要体现在输出项）。
- 不同功能、不同缓存命中率的换算差别很大，面板里的两个系数可以自己改。

## 其他

- 界面语言跟随浏览器（中文 / English）。
- 数据默认只存本浏览器（IndexedDB + localStorage），不上传任何第三方服务器。
- `kimi.ai` 海外版域名为兼容性尝试，未实测。
- 本项目为非官方工具，与 Kimi / Moonshot 无关；所调用的内部接口随时可能变化导致失效。使用即表示理解以上限制，风险自负。MIT License。
